# WebScrapper

Многопоточный Java-скрапер, который периодически опрашивает несколько публичных API, собирает ссылки на изображения и палитры цветов и сохраняет результаты в JSON или CSV.

## Описание проекта

Программа запускается из командной строки, принимает на вход количество потоков, интервал опроса, список источников и формат вывода. Для каждого указанного источника создаётся задача, которая выполняется в пуле потоков с фиксированным размером. Задача делает асинхронный HTTP-запрос к API, парсит ответ и передаёт нормализованные данные в `OutputWriter`, который дописывает результат в выходной файл.

Поддерживаемые источники:

| Источник | Что возвращает |
|---|---|
| `dog-api` | Случайное изображение собаки (URL) |
| `neko-api` | Случайное изображение неко (URL) |
| `colormind-api` | Палитра из 5 цветов в виде ссылок на colorhexa.com |

Работа продолжается до тех пор, пока счётчик `CountDownLatch` не дойдёт до нуля (по умолчанию — 9 итераций), после чего пул потоков корректно завершается.

## Как это реализовано

**Точка входа — `Main`.** Метод `extractingArgs` валидирует аргументы командной строки: проверяет их количество, положительность `maxThreads` и `timeOut`, допустимость формата вывода (`json`/`csv`) и извлекает список сервисов. При ошибке логирует исключение и возвращает `false`, из-за чего `main` завершается с кодом 1. Метод `scrape` создаёт `ExecutorService` с фиксированным пулом, `CountDownLatch` на 9 и для каждого имени сервиса ставит в очередь соответствующий `Scrapper`. Отдельный поток ждёт `latch.await()`, после чего выставляет `running=false` и вызывает `executor.shutdown()`.

**`Scrapper`** реализует `Runnable`. В `run()` вызывает `entity.fetchData()`, затем в `finally` уменьшает счётчик защёлки и, если работа ещё не остановлена и счётчик не ноль, спит `timeOut` секунд и перепланирует себя же через `executor.execute(...)`. Так реализован периодический опрос без внешнего планировщика.

**`Api`** — интерфейс с дефолтными методами `fetchData()` и `sendAsyncRequest()`. `fetchData` собирает `HttpRequest` через `HttpRequest.newBuilder().uri(URI.create(getSource()))`, а `sendAsyncRequest` использует `HttpClient.sendAsync(...)` с `BodyHandlers.ofString()`, затем через `thenApplyAsync`/`thenAcceptAsync` передаёт тело ответа в `handleApiResponse`. Исключения (`CompletionException`, `NullPointerException`, `SecurityException`) логируются. Конкретные реализации — `DogApi`, `NekoApi`, `ColorApi` — переопределяют `handleApiResponse`, `getHttpClient`, `getLogger` и `getSource`. `ColorApi` дополнительно переопределяет `fetchData`, потому что Colormind принимает POST с JSON-телом `{"model":"default"}`.

**`Data`** — простая модель с полями `apiName` и `List<String> data`, используется для сериализации.

**`OutputWriter`** отвечает за запись результатов: в зависимости от статического поля `type` пишет либо JSON через Jackson (`ObjectMapper`), либо CSV через `commons-csv`. При JSON-режиме дописывает объекты в массив в `output.json`, в CSV-режиме — строки.

**Логирование** построено на Log4j2 (`LogManager.getLogger`). В лог пишутся успешные записи (`INFO scrapper.OutputWriter`), ошибки парсинга (`ERROR scrapper.api.ColorApi`), некорректные аргументы (`ERROR scrapper.Main`) и предупреждения о неизвестных источниках (`WARN scrapper.Main - Unsupported source ... Skipped...`).

## Как запускать

Сборка и запуск проекта осуществляются через Maven. Для запуска используйте следующую команду:

```bash 
  java -jar target/2903-1.0-SNAPSHOT.jar <maxThreads> <timeOut> <service1> [service2 ...] <json|csv>
```
**Параметры:**

- `maxThreads` — размер пула потоков (целое > 0);
- `timeOut` — интервал между опросами в секундах (целое > 0);
- `service...` — один или несколько источников: `dog-api`, `neko-api`, `colormind-api`;
- последний аргумент — формат вывода: `json` или `csv`.

**Пример:**

```bash 
  java -jar target/2903-1.0-SNAPSHOT.jar 2 5 dog-api neko-api colormind-api json
```

Результат дописывается в output.json (или CSV-файл) в рабочей директории.

**Формат JSON-записи:**

```json
{
  "apiName": "dog-api",
  "data": ["https://images.dog.ceo/breeds/african-wild/n02116738_6038.jpg"]
}
```

Неизвестные имена источников не прерывают работу — они логируются как `WARN` и пропускаются. Некорректные аргументы приводят к записи ошибки в лог и выходу с кодом 1.

## Итоги проекта

В ходе выполнения работы был реализован полноценный многопоточный веб-скрапер на языке Java. Проект успешно решает поставленную задачу: программа в фоновом режиме опрашивает несколько независимых внешних API, корректно парсит разнородные ответы (JSON и массивы чисел) и надежно сохраняет результаты в файлы форматов JSON и CSV.

**Что было реализовано и изучено:**

1. **Многопоточность и конкурентность:** На практике применены `ExecutorService` для управления пулом потоков и `CountDownLatch` для контроля количества итераций. Реализован механизм циклического перепланирования задач (`Scrapper`) без использования тяжеловесных внешних планировщиков.
2. **Асинхронный ввод-вывод:** Взаимодействие с сетью построено на современных возможностях Java (`java.net.http.HttpClient`) с использованием асинхронных цепочек `CompletableFuture` (`sendAsync`, `thenApplyAsync`, `thenAcceptAsync`), что позволяет не блокировать потоки во время ожидания ответа от сервера.
3. **Работа с данными:** Освоена десериализация JSON-ответов с помощью библиотеки Jackson, а также конвертация данных и их запись в файлы (Jackson для JSON, Apache Commons CSV для CSV).
4. **Архитектура и ООП:** Проект имеет четкое разделение ответственности. Использован интерфейс `Api` с дефолтными методами для избежания дублирования кода при работе с разными эндпоинтами.
5. **Тестирование:** Написано широкое покрытие тестами (Unit-тесты) с использованием JUnit 5 и Mockito. Достигнут высокий процент покрытия кода (94% строк), протестированы как позитивные сценарии, так и обработка ошибок (неверные аргументы, сбои сети). Для тестирования приватных методов `Main` применена рефлексия.
